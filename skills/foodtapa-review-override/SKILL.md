# 관리자 허용

## 시작 전에

- 이 스킬은 음처기넷 플러그인의 세부 스킬이다. 작업 폴더와 접속 정보, 보낼 사이트, 지켜야 할 규칙, 실행 환경, 전송 방법(인증)은 메인 스킬 `foodtapa-notion-review`의 같은 이름 절을 따른다. 이 대화에서 아직 읽지 않았으면 이 스킬 폴더 옆의 `../foodtapa-notion-review/SKILL.md`에서 그 절을 먼저 읽는다.
- 사이트 API 판단 기준은 `../foodtapa-notion-review/references/api.md`를 따른다. 사이트 API는 바뀔 수 있으므로 판단은 사이트 응답, 사이트가 알려 주는 목록, 이 지침 순서로 한다.
- 사이트가 `200`·`201`·`202`가 아닌 응답을 주면 `foodtapa-review-errors` 스킬을 불러 따른다. 부를 수 없으면 `../foodtapa-review-errors/SKILL.md`를 읽는다.
- 아래 명령의 `$api`는 메인 스킬 "전송 방법"과 같이 정한다.

  ```sh
  set -a; . ./foodtapa-api.env; set +a
  api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
  ```
- 허용할 원고의 노션 링크나 원고 ID가 요청에 없으면 그것 하나만 묻는다.

## AI에게: 관리자 허용 요청

개인정보가 아닌 값이 개인정보로 잡혔거나(예: 모델 번호가 전화번호로 잡힘) AI 검수 판정이 맞지 않을 때, 사람이 오탐이라고 판단하면 원고를 고치지 않고 그 버전을 통과시킬 수 있다. AI가 오탐인지 스스로 정하지 않는다. 사람이 **허용**을 요청했을 때만 진행한다.

1. `foodtapa-review-status` 스킬의 "최신 접수 찾기"로 이 원고의 최신 접수 건을 찾는다. 최신 건이 `needs_revision`·`insufficient_evidence`가 아니면 허용하지 않고 현재 상태만 알린다.
2. 허용 사유를 사람에게 받는다. 사유는 필수이며 짐작해 채우지 않는다. 1,000자 이내로 쓰고 이름·연락처 같은 개인정보는 넣지 않는다.
3. 아래 표를 보여 주고 **허용** 답을 받는다.

   | 항목 | 값 |
   | --- | --- |
   | 원고 ID / 버전 / 접수 번호 | |
   | 허용할 지적 | 위치와 항목(예: 본문 · 개인정보 전화번호) |
   | 허용 사유 | |

4. 같은 인증 방식으로 `"$api/{접수 id}/override"`에 `{"reason":"허용 사유"}`를 POST로 보낸다. 사유는 셸 변수나 파일로 넘겨 JSON 따옴표가 깨지지 않게 한다.
5. 응답의 `status`가 `passed`이고 `override`에 사유가 담겼는지 확인해 보고한다. 지적은 기록으로 남아 `checks`에 미충족으로 계속 보인다고 알린다. 이후 발행은 `foodtapa-review-publish` 스킬대로 한다.

- `409`는 최신 버전이 아니거나 허용할 수 없는 상태, 또는 개인정보 제거 표시가 남은 원고다. `422`는 사유가 비었거나 길거나 개인정보로 보이는 값이 있는 경우다. 응답의 `message`를 그대로 알리고 반복하지 않는다.
- 이미 허용한 건에 다시 보내면 처음 기록이 그대로 돌아온다.

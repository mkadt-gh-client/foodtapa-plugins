# 노션 원고 검수 보내기

노션 원고 페이지 하나를 읽어 제목·본문·댓글·대댓글로 나누고 음처기넷 사이트의 외부 원고 검수로 보낸다. 보내기 전에 나눈 결과를 보여 주고 사람이 확인한 뒤에만 전송한다. 수정 반영을 요청받으면 사이트의 검수 의견대로 고칠 안을 보여 주고, 사람이 확인하면 노션 원고를 고쳐 새 버전으로 다시 보낸다.

## 자동 업데이트 켜기 (Claude 앱)

- 요청을 처리하기 전에, Claude 앱에서 실행 중이면 사용자 설정 파일(맥 `~/.claude/settings.json`, 윈도우 `%USERPROFILE%\.claude\settings.json`)의 `extraKnownMarketplaces` 안 `foodtapa-plugins` 항목에 `"autoUpdate": true`가 있는지 확인한다.
- 없으면 그 항목에 `"autoUpdate": true` 한 줄만 추가한다. 다른 항목과 값은 바꾸지 않고, 고친 뒤 JSON이 올바른지 확인한다. 수정 허용을 묻기 전에 사람에게 "음처기넷 스킬이 새 버전을 자동으로 받도록 설정합니다. 허용을 눌러 주세요"라고 알린다.
- 이미 있거나 `foodtapa-plugins` 항목이 없으면 아무것도 바꾸지 않는다. ChatGPT 앱(Codex)에서는 이 단계를 건너뛴다.
- 이 단계는 다른 진행을 막지 않는다. 결과는 끝났을 때 보고에 "자동 업데이트: 켜짐·이미 켜짐·해당 없음" 중 하나로 한 줄만 적는다.

## 작업 폴더와 접속 정보

- **작업 폴더는 사용자 폴더 안의 `foodtapa` 폴더다.** 맥은 `~/foodtapa`, 윈도우는 `%USERPROFILE%\foodtapa`다. 이 스킬의 모든 명령은 이 폴더로 이동한 뒤 실행하고, 아래 지침의 "작업 폴더"도 이 폴더를 뜻한다. 대화를 연 폴더가 달라도 이 폴더를 쓴다.
- 접속 정보는 작업 폴더의 `foodtapa-api.env`에 있다. 파일이 없거나 `FOODTAPA_USER`·`FOODTAPA_APP_PASSWORD`가 비어 있으면 진행하지 않고 `foodtapa-setup` 스킬을 불러 따른다. 부를 수 없으면 이 스킬 폴더 옆의 `../foodtapa-setup/SKILL.md`를 읽는다. 설정 스킬은 파일을 편집기로 열어 사람이 직접 값을 넣게 한다.
- **아이디·비밀번호를 대화창으로 받지 않는다.** 사람이 대화창에 붙여 넣으면 그 값을 쓰지 말고 `foodtapa-setup` 스킬의 "대화창에 비밀번호가 올라왔을 때"를 따른다.
- 파일을 읽기 전에 대화마다 한 번 아래로 정리한다. 윈도우 메모장 줄바꿈과 비밀번호의 띄어쓰기가 남아 있으면 맥에서 파일을 읽지 못한다. 워드프레스는 애플리케이션 비밀번호의 띄어쓰기를 무시한다.

  ```sh
  sed -i '' -e $'s/\r$//' -e '/^FOODTAPA_SITE=/s/[[:space:]]//g' -e '/^FOODTAPA_APP_PASSWORD=/s/[[:space:]]//g' foodtapa-api.env
  ```

## 보낼 사이트

- **지금은 kincomm(`https://kincomm.kinsta.cloud`)으로만 보낸다.** 음식물처리기.net은 아직 QA 용도라 원고를 보내지 않는다.
- 시작할 때 `FOODTAPA_SITE`가 kincomm 주소인지 확인한다. 아이디·비밀번호는 출력하지 않고 사이트 주소만 본다. 다른 주소면 보내지 말고 `FOODTAPA_SITE=https://kincomm.kinsta.cloud`로 바꾸고 그 사이트의 아이디·애플리케이션 비밀번호를 넣어 달라고 안내한 뒤 멈춘다.

  ```sh
  grep -qx 'FOODTAPA_SITE=https://kincomm.kinsta.cloud/\{0,1\}' foodtapa-api.env && echo "kincomm" || echo "kincomm 아님"
  ```
- 아래 "확인 표"와 발행·예약 표, 관리자 허용 표의 맨 위에 **보낼 사이트** 행을 넣고 "kincomm"으로 적는다.

## 세부 스킬

이 스킬은 음처기넷 플러그인의 메인 스킬이다. 같은 플러그인에 아래 세부 스킬이 함께 설치된다. 해당하는 상황이 되면 그 스킬을 불러 따른다. 부를 수 없으면 이 스킬 폴더 옆의 `../<스킬 이름>/SKILL.md`를 읽는다. 세부 스킬은 접속 정보·보낼 사이트·지켜야 할 규칙·전송 방법을 이 메인 스킬에서 가져다 쓴다.

| 스킬 | 쓸 때 |
| --- | --- |
| `foodtapa-tutorial` | 처음 쓰는 사람이 노션 없이 샘플 원고로 접속 설정부터 발행 연습까지 따라 해 볼 때 |
| `foodtapa-setup` | 접속 정보 파일이 없거나 비었을 때, 비밀번호를 바꿀 때, `401`·`403`이 났을 때 |
| `foodtapa-notion-fill` | 아래 "필수 정보 점검"에서 걸렸을 때, 보내기 전에 빠진 값을 점검하고 함께 채울 때 |
| `foodtapa-review-status` | 검수 결과·발행 상태만 확인할 때. 원고를 다시 보내지 않는다 |
| `foodtapa-notion-revise` | 수정 필요·근거 부족 원고를 검수 의견대로 고쳐 새 버전으로 다시 보낼 때 |
| `foodtapa-review-override` | 사람이 오탐이라고 판단해 관리자 허용을 요청할 때 |
| `foodtapa-review-publish` | 검수 통과 원고를 예약·공개할 때(아래 진행 순서 7단계) |
| `foodtapa-review-errors` | 사이트가 `200`·`201`·`202`가 아닌 응답을 줬을 때, 검수가 `error`일 때, 10번 조회해도 끝나지 않을 때 |

- `references/api.md`는 사이트 API 기준이다. 작업을 시작할 때(라우트 목록 확인), 분류 이름을 대조할 때, 이 지침에 없는 응답 항목이나 조회 조건이 필요할 때 읽는다.
- **사이트 API는 바뀔 수 있다.** 이 지침과 세부 스킬의 값은 작성 시점 기준이다. 판단은 사이트 응답, 사이트가 알려 주는 라우트 목록·분류 목록, 이 지침 순서로 한다. 지침에 없는 응답은 짐작하지 않고 그대로 알린 뒤 멈춘다.

## 노션 연결

- 노션은 AI 앱의 노션 커넥터로 읽고 쓴다. 노션 워크스페이스 멤버 계정으로 로그인해야 하며 게스트 계정은 연결되지 않는다.
  - Claude 데스크탑 앱: **설정 → 커넥터**에서 Notion을 추가하고 로그인한다.
  - ChatGPT 앱(Codex): 앱 설정에서 Notion 커넥터를 찾아 연결하고 로그인한다.
- **커넥터를 연결했는데 Code 탭에서 노션을 못 읽을 때**(인증이 필요하다거나 로그인이 거부됐다고 나올 때)는 Code 탭에서도 한 번 더 로그인해야 한다. 아래처럼 안내하고 멈춘다.
  1. Code 탭 입력창에 `/mcp`를 입력하고 **mcp**(Manage MCP servers)를 고른다.
  2. 목록에서 **claude.ai Notion**을 고르고 **Authenticate**(또는 Re-authenticate)를 누른다.
  3. 브라우저에 "데스크톱 앱에서 완료하기" 화면이 뜨면 본인 Claude 계정인지 확인하고 **데스크톱 앱 열기**를 누른 뒤, 노션 승인 화면에서 원고가 있는 워크스페이스를 허용한다.
  4. 끝나면 같은 요청을 다시 보낸다.
- 커넥터를 쓸 수 없을 때만 노션 토큰을 쓴다. 노션의 **설정 → 연결 → 통합 개발**에서 내부 통합을 만들고, 원고를 모으는 상위 페이지의 **연결** 메뉴에 그 통합을 추가한 뒤 토큰을 `NOTION_TOKEN`에 넣는다.

## 샘플 원고

- 이 스킬 폴더의 `samples/`에 시험용 원고 두 편이 있다. `01-pass-LEARN-9001.md`는 검수를 통과하는 예시, `02-revise-LEARN-9003.md`는 본문이 350자에 못 미쳐 수정 필요가 나오는 예시다. 2번은 분량을 고쳐 다시 보내도 AI가 댓글의 사용 경험 단정을 근거 부족으로 판정할 수 있다(2026-11-25 시험). AI 판정이라 결과가 매번 같지는 않다고 미리 알린다. 원자료 ID·원고 ID·분류 같은 관리 정보는 시험용 가상값이다.
- 사람이 샘플로 시험하고 싶다고 하면 어느 샘플인지와 노션의 어느 페이지 아래에 만들지 묻는다. 노션 커넥터로 그 아래에 새 페이지를 만들어 샘플의 첫 줄 제목을 페이지 제목으로, 나머지를 본문으로 옮긴다. 들여쓴 댓글은 들여쓴 목록 그대로 둔다. 만든 페이지 링크로 검수 보내기를 진행한다. 커넥터로 만들 수 없으면 샘플 내용을 보여 주고 노션 새 페이지에 붙여 넣어 달라고 한다.
- 샘플 파일을 노션 대신 직접 읽어 보내지 않는다. 노션을 거쳐야 실제 사용과 같은 흐름이 된다. 예외는 노션 없이 따라 하는 `foodtapa-tutorial` 연습뿐이다.
- 노션 연결 전에 먼저 따라 해 보고 싶다고 하면 `foodtapa-tutorial` 스킬을 따른다.

## 맥과 윈도우

- 아래 명령은 맥 기준이다. 윈도우에서는 같은 원칙(비밀값은 변수로만, 화면·명령 인자에 출력 금지)으로 PowerShell에 맞게 바꿔 실행한다. 윈도우의 curl은 `curl.exe`로 부른다.
- `jq`나 `shasum`이 없으면 같은 결과를 내는 다른 방법(PowerShell `Get-FileHash`, `ConvertFrom-Json` 등)을 쓴다. 버전 해시는 키를 정렬한 한 줄 JSON에 줄바꿈 하나를 붙인 UTF-8 바이트의 SHA-256이어야 한다.

## AI에게: 지켜야 할 규칙

사람이 이 지침대로 보내 달라고 요청했으면 "진행할까요?"처럼 되묻지 않는다. 링크가 요청에 있으면 바로 시작하고, 없으면 그것 하나만 묻는다. 전송 직전의 확인(아래 4단계)만은 반드시 받는다.

1. **한 번에 원고 한 편만 보낸다.** 링크의 페이지 하나만 읽는다. 하위 페이지나 같은 묶음의 다른 원고를 함께 보내지 않는다.
2. **페이지 본문만 읽는다.** 노션의 댓글 기능(페이지나 블록에 달린 토론·검수 의견)은 원고가 아니다. 읽지 않고 보내지 않는다. 원고 속 회원 댓글은 페이지 본문에 적혀 있다.
3. **원고 문장을 바꾸지 않는다.** 글자·줄바꿈·말투를 고치거나 요약하지 않고 페이지에 적힌 그대로 옮긴다. 문제가 보여도 고치지 말고 사람에게 알린다. 고치는 일은 노션에서 사람이 한다. 예외는 사람이 **수정 반영**을 요청했을 때뿐이다. 이때도 `foodtapa-notion-revise` 스킬대로 사이트가 지적한 곳만 고치고, 사람이 확인한 안만 노션에 적는다.
4. **없는 값을 만들지 않는다.** 원자료 ID, 유형, 키워드처럼 페이지에 없는 값은 짐작해 채우지 않고 사람에게 묻는다. 예외는 아래 표에 "AI가 정함"이라고 적힌 칸뿐이다.
5. **비밀값을 다루지 않는다.** `foodtapa-api.env`를 화면에 출력하거나 내용을 읽어 대화에 옮기지 않는다. 명령 인자에도 비밀값을 직접 넣지 않는다. 아래 전송 방법처럼 셸 변수로만 넘긴다.
6. **개인정보를 보내지 않는다.** 실명, 연락처, 주소, 상담 원문이 원고에 보이면 보내지 않고 위치만 알린다.
7. **사람에게 무언가를 부탁할 때는 바로 따라 할 수 있게 쓴다.** 답변 맨 끝에 한 덩어리로 두고 위아래를 구분선 `---`으로 감싼다. 구분선 바로 윗줄은 빈 줄로 둔다.

   ```markdown
   ---

   ### 👉 다음에 하실 일

   > **위 표에서 댓글과 대댓글 연결이 맞는지 확인해 주세요.**
   >
   > 맞으면 **전송**, 고칠 곳이 있으면 그 내용을 답해 주세요.

   ---
   ```

## AI에게: 실행 환경

- 터미널 명령을 실행할 수 없는 대화(일반 ChatGPT·Claude 대화)면 "Claude 데스크탑 앱의 Code 탭이나 ChatGPT 앱의 Work에서 다시 요청해 주세요"라고 안내하고 멈춘다.
- 작업 폴더로 이동해 `foodtapa-api.env`가 있는지 확인한다. 없거나 값이 비었으면 `foodtapa-setup` 스킬을 따른다. 내용을 확인할 때도 값은 출력하지 않고 네 이름이 있는지만 본다.
  ```sh
  for k in FOODTAPA_SITE FOODTAPA_USER FOODTAPA_APP_PASSWORD NOTION_TOKEN; do grep -q "^$k=." foodtapa-api.env && echo "$k 있음" || echo "$k 비어 있음"; done
  ```
- **사이트 AI 연결 확인**: 대화에서 처음 원고를 보내기 전에 한 번, 사이트에 검수용 AI 키가 있는지 확인한다. 모델 조회만 하므로 생성 비용이 들지 않는다.
  ```sh
  set -a; . ./foodtapa-api.env; set +a
  printf 'user = "%s:%s"\n' "$FOODTAPA_USER" "$FOODTAPA_APP_PASSWORD" | curl -sS -K - -o ai-check.json -w 'HTTP %{http_code}\n' \
    -H 'Content-Type: application/json' --data '{}' "$FOODTAPA_SITE/wp-json/fdt/v1/workflows/ai-status/check"
  jq -r '.providers | to_entries[] | select((.value.models|length)>0) | "\(.value.label): \(.value.health.label)"' ai-check.json 2>/dev/null; rm -f ai-check.json
  ```
  - 이 사이트가 쓰는 제공사(위 결과에 나온 이름)가 `미등록`이면 보내지 않는다. 보내도 검수가 오류로 끝난다. "사이트에 검수용 AI 키가 없습니다. 사이트 관리자로 로그인한 뒤 **자동화 → AI API 연결**(`$FOODTAPA_SITE/wp-admin/admin.php?page=fdtw-ai-connection`)에서 키를 등록해 주세요"라고 알리고 멈춘다. 사람이 원하면 `foodtapa-setup` 스킬의 "AI 키 등록"으로 등록을 돕는다.
  - `키를 읽지 못함`·`연결 실패`면 보내지 않는다. 결과의 안내 문구를 전하고 관리자 화면에서 키를 확인해 달라고 한 뒤 멈춘다.
  - `연결됨`·`연결 확인 필요`·`사용 중인 단계 없음`이면 그대로 진행한다.
  - `HTTP`가 `200`이 아니면(예: 계정에 사이트 관리자 권한이 없어 `403`) 확인을 건너뛰고 진행한다. 검수가 오류로 끝나면 그때 원인을 찾는다.
- **노션 읽기**: AI 앱의 노션 커넥터(MCP)로 페이지와 하위 블록을 읽는다. 커넥터가 없고 `NOTION_TOKEN`이 채워져 있을 때만 `NOTION_TOKEN`으로 노션 API의 블록 목록(`GET https://api.notion.com/v1/blocks/{페이지 ID}/children`, 하위 블록이 있으면 재귀)을 읽는다. 둘 다 안 되면 노션 연결이나 토큰 준비를 안내하고 멈춘다. 404가 나면 그 페이지에 통합이 연결되지 않은 것이다.
- Windows에서는 아래 셸 명령을 같은 원칙(비밀값은 변수로만, 출력 금지)으로 PowerShell에 맞게 바꿔 실행한다.

## AI에게: 진행 순서

단계를 마칠 때마다 답변 맨 첫 줄에 완료를 표시한다. 실패하거나 건너뛴 단계는 ✅ 대신 ❌ 또는 ⏭️와 이유를 적는다.

```markdown
---

### ✅ 2단계 완료 · 글과 댓글 나누기

---
```

| 단계 | 할 일 |
| --- | --- |
| 1. 페이지 읽기 | 링크의 페이지 제목, 속성, 본문 블록을 하위 블록까지 읽는다. 블록 종류와 들여쓰기(부모·자식 관계)를 함께 본다. |
| 2. 글과 댓글 나누기 | 아래 "나누는 기준"대로 제목·본문·댓글·대댓글을 가른다. 나눈 뒤 아래 "필수 정보 점검"을 한다. 빠지거나 틀린 항목이 있으면 3단계로 넘어가지 않는다. |
| 3. 전송할 JSON 만들기 | 아래 "필드 채우기" 표대로 `manuscript.json`을 작업 폴더에 UTF-8로 저장한다. 본문에 사진이 있으면 아래 "사진 넣기"대로 내려받아 한 장씩 올리고 받은 `upload_id`를 `post.images`에 넣는다. 올린 사진은 발행 전까지 공개되지 않고, 올린 지 24시간이 지나면 업로드 원본은 지워진다(원고에 넣은 사진은 접수 때 따로 보관된다). |
| 4. 사람 확인 | 아래 "확인 표"를 보여 주고 **전송** 답을 받는다. 고칠 곳을 답하면 노션 원문을 고쳐 달라고 하거나 나누기를 다시 해서 표를 다시 보여 준다. |
| 5. 전송 | 아래 "전송 방법"으로 보낸다. |
| 6. 결과 확인 | 접수 `id`로 상태를 1분 간격으로 최대 10번 조회한다. `passed`·`needs_revision`·`insufficient_evidence`·`error`가 되면 멈추고 보고한다. 10번 안에 끝나지 않으면 접수 번호와 함께 나중에 사이트에서 확인하라고 알린다. |
| 7. 발행·예약 | `passed`이고 페이지에 예약 일시가 있으면 `foodtapa-review-publish` 스킬대로 진행한다. 예약 일시가 없으면 이 단계는 건너뛴다. |

### 나누는 기준

- **제목**은 페이지 제목이나 본문 맨 위의 원고 제목이다. "LEARN-0001"처럼 관리용 번호만 붙은 페이지 제목이면 번호를 뺀 원고 제목을 쓴다. 어느 것이 원고 제목인지 애매하면 묻는다.
- **본문**은 제목 다음부터 첫 댓글 전까지의 원고 글이다. 관리용 메모, 원자료 정보, 검수 기록, 키워드 표시, 수정 전후 비교는 본문이 아니다.
- **댓글이 시작되는 곳**은 "댓글" 제목이나 구분선, 또는 "댓글1", "회원A:"처럼 화자가 붙은 첫 발화다.
- **대댓글의 부모**는 다음 순서로 정한다.
  1. 들여쓴 목록이면 바로 위 단계의 항목이 부모다.
  2. "1-1", "↳", "└", "→1"처럼 부모 번호나 답글 표시가 있으면 그 번호의 댓글이 부모다.
  3. 둘 다 없으면 부모를 짐작하지 않고 사람에게 묻는다.
- 같은 원고를 수정해 다시 보낼 때는 처음 보낼 때와 같은 방식으로 댓글 ID를 만든다.

### 필요한 값 찾기

노션 원고를 적는 형태는 정해져 있지 않다. 원고 DB의 칸(페이지 속성)에 둘 수도 있고, 본문 위쪽에 목록이나 표로 둘 수도 있으며, 칸 이름도 사람마다 다를 수 있다. 형태와 이름에 매이지 말고 아래 **값의 뜻**으로 찾는다. 아래 "필드 채우기"의 값은 여기서 찾은 값이다.

| 필요한 값 | 뜻 | 이렇게 적혀 있을 수 있다(예시일 뿐) | API 필드와 형식 |
| --- | --- | --- | --- |
| 원자료 ID | 원고를 만든 바탕 자료(상담·카페 글 등)의 식별자 | 원자료 ID, S소스, 원문 ID, 소스 번호 | `source_id`. 영문·숫자로 시작하고 영문·숫자와 `_ . : -`만 |
| 원고 ID | 이 원고 한 편의 고유 번호. 고쳐 다시 보내도 같아야 한다 | 원고 ID, 원고 번호, LEARN-0000 | `manuscript_id`. 형식은 원자료 ID와 같다 |
| 활용 범위 | 이 원고가 다루는 질문과 범위 | 활용 범위, 검색질문, 다루는 질문 | `source_scope`. 문장 그대로 |
| 유형 | 원고의 쓰임새 | 유형, 원고 유형, 검색형·생활형·일상형 | `mode`. 검색형 `search`, 생활형 `life`, 일상형 `daily` |
| 목표 키워드 | 검색형 원고가 노리는 검색어 하나 | 목표 키워드, 키워드, 타깃 키워드 | `keyword`. 검색형이면 필수 |
| 글 종류 | 사이트에 올라갈 글의 종류 | 글 종류, 게시판, 질문·후기·정보글 | `post.type`. 질문 `question`, 후기 `review`, 정보글 `guide` |
| 분류 | 제품군·브랜드·모델·주제·상황 | 같은 이름의 칸·목록, 태그 | `post.taxonomies`의 `product`·`brand`·`model`·`topic`·`situation`. 사이트에 등록된 이름만 |
| 근거 | 단정한 사실을 뒷받침하는 정제된 자료 | 근거, 출처, 참고 자료 | `evidence`. 선택 |
| 예약 일시 | 발행할 날짜와 시각 | 예약 일시, 발행일, 게시 예정 | 접수 때는 보내지 않고 발행 때만 쓴다 |

- **어디서 찾았는지 보여 준다.** 아래 "확인 표"에 값마다 읽은 곳(예: "DB 칸 `S소스`", "본문 관리 정보 3번째 줄")을 적는다. 뜻이 맞는지 애매한 칸(예: `번호`가 원고 ID인지 정렬 번호인지)은 짐작하지 않고 묻는다.
- **한 번 확인한 대응은 다시 묻지 않는다.** 같은 대화에서 같은 형태의 원고를 이어 보내면 처음 확인한 대응을 쓴다.
- 값이 비었거나 "없음", "-"이면 빈 값으로 본다. 분류에서는 빈 목록이다.
- 본문 글자 수, 댓글 수, 비고, 작업 메모처럼 위 표에 없는 칸은 참고용이라 보내지 않는다. 본문 글자 수는 AI가 직접 센다.
- 같은 값이 두 곳에 다르게 적혀 있으면 어느 쪽이 맞는지 묻는다.

| 항목 | 점검 |
| --- | --- |
| 원자료 ID, 원고 ID | 있는지. 영문·숫자로 시작하고 영문·숫자와 `_ . : -`만 쓰는지(한글·공백 불가) |
| 활용 범위 | 있는지 |
| 유형 | 검색형·생활형·일상형 중 하나인지 |
| 목표 키워드 | 검색형이면 있는지. 있으면 제목에 정확히 한 번 들어가는지 |
| 분류 | 적힌 이름이 사이트에 등록된 이름과 글자까지 같은지. 축마다 `"$FOODTAPA_SITE/wp-json/wp/v2/fdt-brand?per_page=100&_fields=name"`처럼(`product`·`brand`·`model`·`topic`·`situation`) 같은 인증으로 조회해 대조한다 |

- 표 아래에 "노션 원고에 채운 뒤 같은 링크로 다시 요청해 주세요"라고 안내한다. 사람이 함께 채워 달라고 하면 `foodtapa-notion-fill` 스킬을 따른다. 어디에 채울지는 그 원고가 이미 쓰는 형태(DB 칸이면 칸, 본문 목록이면 목록)를 따른다. 사람이 대화창에 값을 답하면 그 값으로 진행하되, 수정 반영 때도 같은 값이 필요하니 노션에도 적어 두라고 한 줄 알린다.

### 사진 넣기

- 정보글(`guide`)에는 사진을 넣지 않는다. 정보글 페이지에 사진이 있으면 보내지 말고 사람에게 알린다.
- 제목부터 첫 댓글 전까지 본문에 있는 노션 이미지 블록만 넣는다. 위에서부터 차례로 `photo-1`, `photo-2`처럼 `id`를 붙인다. 같은 원고를 다시 보낼 때도 같은 순서로 붙인다.
- 이미지 블록의 파일 주소(노션에 올린 파일이면 `image.file.url`, 외부 링크면 `image.external.url`)에서 작업 폴더의 `photos/`로 내려받는다. 노션 파일 주소는 1시간쯤 지나면 만료되므로 만료됐으면 페이지를 다시 읽어 새 주소를 받는다. 주소는 화면에 출력하지 않는다.
- 사진은 원고 JSON에 base64로 넣지 않는다. 내려받은 사진을 한 장씩 사이트에 올리고 응답의 `upload_id`를 받는다. 인증은 "전송 방법"과 같이 표준 입력으로 넘긴다.
  ```sh
  set -a; . ./foodtapa-api.env; set +a
  api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
  printf 'user = "%s:%s"\n' "$FOODTAPA_USER" "$FOODTAPA_APP_PASSWORD" | curl -sS -K - \
    -F "file=@photos/photo-1.jpg" -w '\nHTTP %{http_code}\n' "$api/images"
  ```
- `201`은 새로 올림, `200`은 같은 사진을 이미 올려 기존 `upload_id`를 돌려준 것이다. `422`면 응답의 `data.reason`(형식·5MB·화소)을 알리고, 직접 바꾸지 말고 사람에게 노션의 사진을 바꿔 달라고 한다.
- `post.images`에는 사진마다 `{"id": "photo-1", "upload_id": "응답의 upload_id", "alt": ""}`를 넣는다.
- 수정 반영으로 새 버전을 보낼 때는 내려받은 사진마다 SHA-256을 계산해(`shasum -a 256 사진파일`) 직전 접수 상태 조회 응답 `payload.post.images`의 `sha256`과 비교한다. 같은 사진은 올리지 않고 `{"id": "photo-1", "sha256": "그 값", "alt": ""}`로 넣는다. 새로 생긴 사진만 올려 `upload_id`로 넣고, 노션에서 빠진 사진은 목록에서 뺀다. 확인 표에 사진마다 재사용·새로 올림을 표시한다. `upload_id`는 24시간 동안만 쓸 수 있다. 접수가 `post.images[순번].upload_id` 오류로 돌아오면 그 사진을 다시 올려 새 `upload_id`로 바꿔 넣는다.
- 이미지 캡션이 있으면 `alt`에 넣는다. HTML 없이 한 줄 200자 이내로 쓰고 이름·연락처 같은 개인정보는 넣지 않는다. 캡션이 없으면 빈 문자열로 둔다.
- 사이트는 JPG·PNG·WEBP 사진을 장당 5MB 이하로 10장까지 받는다. 형식이 다르거나(GIF·HEIC 등) 크기를 넘으면 직접 바꾸지 말고 사람에게 알려 노션의 사진을 바꿔 달라고 한다.
- 사진을 본문에 `<img>` 태그나 `style`의 배경 이미지(`url()`)로 넣지 않는다. 댓글 사이에 있는 사진은 보낼 수 없으니 사람에게 알리고 어떻게 할지 묻는다.

페이지의 **예약 일시**는 `manuscript.json`에 넣지 않는다. 검수를 통과한 뒤 7단계 발행 요청에만 쓴다.

**버전 만들기**: 처음 보내거나 원고를 고쳤을 때는 `version`을 비우고 `notion_url`을 뺀 JSON을 키 순서대로 정렬해 한 줄로 만든다. SHA-256 앞 12자리에 `v-`를 붙인다.

```sh
canonical=$(jq -ceS '.version = "" | del(.notion_url)' manuscript.json) &&
  v="v-$(printf '%s\n' "$canonical" | shasum -a 256 | cut -c1-12)"
```

이 값을 `version`에 넣어 다시 저장한다. 같은 원고를 재전송하거나 노션 링크만 바꿀 때는 처음 보낸 `version`을 그대로 쓴다. 같은 사진을 다시 올려 `upload_id`만 바꿀 때도 그대로 쓴다.

### 전송 방법

비밀값이 화면과 명령 인자에 남지 않게 설정 파일을 셸 변수로 읽고, 인증은 표준 입력으로 curl에 넘긴다.

```sh
set -a; . ./foodtapa-api.env; set +a
api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
printf 'user = "%s:%s"\n' "$FOODTAPA_USER" "$FOODTAPA_APP_PASSWORD" | curl -sS -K - \
  -H 'Content-Type: application/json' --data-binary @manuscript.json \
  -w '\nHTTP %{http_code}\n' "$api"
```

- `202`는 새로 접수, `200`은 같은 원고·버전을 이미 접수해 기존 결과를 돌려준 것이다. 응답의 `id`를 기록한다.
- `409`는 같은 원고 ID·버전에 다른 내용이 있거나 원고 ID가 다른 원자료에 묶인 경우다. `422`는 필드가 잘못된 경우다. 응답의 `data.field`(위치)와 `data.reason`(이유)으로 노션의 어느 칸을 고칠지 쉬운 말로 짚고, `message`를 함께 알린다. 같은 요청을 반복하지 않는다.
- `401`·`403`이면 Application Password나 권한 문제다. 비밀값을 확인하겠다며 파일을 출력하지 말고 사람에게 다시 만들어 넣어 달라고 한다.

상태 조회는 같은 방식으로 `"$api/{id}/status"`에 빈 본문 `{}`을 POST로 보낸다.

## AI에게: 막힐 때

- **글과 댓글의 경계가 애매함**: 애매한 줄을 그대로 보여 주고 본문인지 댓글인지 묻는다. 짐작해 보내지 않는다.
- **같은 화자인지 애매함**: 이름이 조금 다른 두 화자(예: "회원A", "A님")가 같은 사람인지 묻는다.
- **노션 페이지를 못 읽음**: 연결이나 토큰 문제인지 알리고 멈춘다. 다른 방법으로 페이지 내용을 구하지 않는다.
- **검수가 `error`**: `foodtapa-review-errors` 스킬의 "검수가 오류로 끝남"대로 원인을 찾는다.

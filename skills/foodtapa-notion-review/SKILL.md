# 노션 원고 검수 보내기

노션 원고 페이지 하나를 읽어 제목·본문·댓글·대댓글로 나누고 푸드타파 사이트의 외부 원고 검수로 보낸다. 보내기 전에 나눈 결과를 보여 주고 사람이 확인한 뒤에만 전송한다. 수정 반영을 요청받으면 사이트의 검수 의견대로 고칠 안을 보여 주고, 사람이 확인하면 노션 원고를 고쳐 새 버전으로 다시 보낸다.

## 작업 폴더와 접속 정보

- **작업 폴더는 사용자 폴더 안의 `foodtapa` 폴더다.** 맥은 `~/foodtapa`, 윈도우는 `%USERPROFILE%\foodtapa`다. 이 스킬의 모든 명령은 이 폴더로 이동한 뒤 실행하고, 아래 지침의 "작업 폴더"도 이 폴더를 뜻한다. 대화를 연 폴더가 달라도 이 폴더를 쓴다.
- 접속 정보는 작업 폴더의 `foodtapa-api.env`에 있다. 파일이 없으면 폴더와 아래 틀을 만들어 두고, 사람에게 파일 위치를 알려 메모장(맥은 텍스트 편집기)으로 열어 빈칸을 채워 달라고 안내한 뒤 멈춘다. 틀에는 비밀값을 넣지 않는다.

  ```text
  FOODTAPA_SITE=https://kincomm.kinsta.cloud
  FOODTAPA_USER=
  FOODTAPA_APP_PASSWORD=
  NOTION_TOKEN=
  ```

- `FOODTAPA_USER`나 `FOODTAPA_APP_PASSWORD`가 비어 있으면 채워 달라고 안내하고 멈춘다. 사람에게 줄 안내는 다음과 같다.
  - `FOODTAPA_USER`는 보낼 사이트의 관리자 아이디, `FOODTAPA_APP_PASSWORD`는 그 사이트 관리자 **사용자 → 프로필 → 애플리케이션 비밀번호**에서 만든 값이다. 다른 사람의 글 편집과 댓글 관리 권한이 있는 관리자 계정이어야 한다.
  - 이 파일은 AI 대화창에 붙여 넣거나 다른 사람에게 보내지 않는다.

## 시험 사이트와 운영 사이트

- 보낼 사이트는 `FOODTAPA_SITE`로 정해진다. `https://kincomm.kinsta.cloud`이면 **시험 사이트**, 그 밖의 주소면 **운영 사이트**다. 값을 확인할 때 아이디·비밀번호는 출력하지 않고 사이트 주소만 본다.
- 시연은 시험 사이트로 한다. 운영으로 옮길 때는 사람이 `foodtapa-api.env`의 사이트 주소·아이디·애플리케이션 비밀번호 세 줄을 운영 사이트 값으로 바꾸면 된다. 운영 사이트의 애플리케이션 비밀번호는 운영 사이트 관리자에서 따로 만든다.
- 아래 "확인 표"와 발행·예약 표, 관리자 허용 표의 맨 위에 **보낼 사이트** 행을 넣고 "시험 사이트" 또는 "운영 사이트(주소)"로 적는다. 운영 사이트로 보낼 때는 표 아래에 "운영 사이트로 보냅니다"라고 한 번 더 알린다.

## 노션 연결

- 노션은 AI 앱의 노션 커넥터로 읽고 쓴다. 노션 워크스페이스 멤버 계정으로 로그인해야 하며 게스트 계정은 연결되지 않는다.
  - Claude 데스크탑 앱: **설정 → 커넥터**에서 Notion을 추가하고 로그인한다.
  - ChatGPT 앱(Codex): 앱 설정에서 Notion 커넥터를 찾아 연결하고 로그인한다.
- 커넥터를 쓸 수 없을 때만 노션 토큰을 쓴다. 노션의 **설정 → 연결 → 통합 개발**에서 내부 통합을 만들고, 원고를 모으는 상위 페이지의 **연결** 메뉴에 그 통합을 추가한 뒤 토큰을 `NOTION_TOKEN`에 넣는다.

## 샘플 원고

- 이 스킬 폴더의 `samples/`에 시험용 원고 두 편이 있다. `01-pass-LEARN-9001.md`는 검수를 통과하는 예시, `02-revise-LEARN-9003.md`는 본문이 350자에 못 미쳐 수정 필요가 나오는 예시다. 원자료 ID·원고 ID·분류 같은 관리 정보는 시험용 가상값이다.
- 사람이 샘플로 시험하고 싶다고 하면 어느 샘플인지와 노션의 어느 페이지 아래에 만들지 묻는다. 노션 커넥터로 그 아래에 새 페이지를 만들어 샘플의 첫 줄 제목을 페이지 제목으로, 나머지를 본문으로 옮긴다. 들여쓴 댓글은 들여쓴 목록 그대로 둔다. 만든 페이지 링크로 검수 보내기를 진행한다. 커넥터로 만들 수 없으면 샘플 내용을 보여 주고 노션 새 페이지에 붙여 넣어 달라고 한다.
- 샘플 파일을 노션 대신 직접 읽어 보내지 않는다. 노션을 거쳐야 실제 사용과 같은 흐름이 된다.
- 샘플은 시험 사이트에서만 보낸다. `FOODTAPA_SITE`가 운영 사이트면 샘플은 보내지 않고 알린다.

## 맥과 윈도우

- 아래 명령은 맥 기준이다. 윈도우에서는 같은 원칙(비밀값은 변수로만, 화면·명령 인자에 출력 금지)으로 PowerShell에 맞게 바꿔 실행한다. 윈도우의 curl은 `curl.exe`로 부른다.
- `jq`나 `shasum`이 없으면 같은 결과를 내는 다른 방법(PowerShell `Get-FileHash`, `ConvertFrom-Json` 등)을 쓴다. 버전 해시는 키를 정렬한 한 줄 JSON에 줄바꿈 하나를 붙인 UTF-8 바이트의 SHA-256이어야 한다.

## AI에게: 지켜야 할 규칙

사람이 이 지침대로 보내 달라고 요청했으면 "진행할까요?"처럼 되묻지 않는다. 링크가 요청에 있으면 바로 시작하고, 없으면 그것 하나만 묻는다. 전송 직전의 확인(아래 4단계)만은 반드시 받는다.

1. **한 번에 원고 한 편만 보낸다.** 링크의 페이지 하나만 읽는다. 하위 페이지나 같은 묶음의 다른 원고를 함께 보내지 않는다.
2. **페이지 본문만 읽는다.** 노션의 댓글 기능(페이지나 블록에 달린 토론·검수 의견)은 원고가 아니다. 읽지 않고 보내지 않는다. 원고 속 회원 댓글은 페이지 본문에 적혀 있다.
3. **원고 문장을 바꾸지 않는다.** 글자·줄바꿈·말투를 고치거나 요약하지 않고 페이지에 적힌 그대로 옮긴다. 문제가 보여도 고치지 말고 사람에게 알린다. 고치는 일은 노션에서 사람이 한다. 예외는 사람이 **수정 반영**을 요청했을 때뿐이다. 이때도 아래 "수정 반영 순서"대로 사이트가 지적한 곳만 고치고, 사람이 확인한 안만 노션에 적는다.
4. **없는 값을 만들지 않는다.** 원자료 ID, 유형, 키워드처럼 페이지에 없는 값은 짐작해 채우지 않고 사람에게 묻는다. 예외는 아래 표에 "AI가 정함"이라고 적힌 칸뿐이다.
5. **비밀값을 다루지 않는다.** `foodtapa-api.env`를 화면에 출력하거나 내용을 읽어 대화에 옮기지 않는다. 명령 인자에도 비밀값을 직접 넣지 않는다. 아래 전송 방법처럼 셸 변수로만 넘긴다.
6. **개인정보를 보내지 않는다.** 실명, 연락처, 주소, 상담 원문이 원고에 보이면 보내지 않고 위치만 알린다.
7. **사람에게 무언가를 부탁할 때는 바로 따라 할 수 있게 쓴다.** 답변 맨 끝에 한 덩어리로 두고 위아래를 구분선 `---`으로 감싼다. 구분선 바로 윗줄은 빈 줄로 둔다.

   ```markdown
   ---

   ### 👉 다음에 하실 일

   > **위 표에서 댓글과 대댓글 연결이 맞는지 확인해 주세요.**
   >
   > 맞으면 **전송**, 고칠 곳이 있으면 그 내용을 답해 주세요.

   ---
   ```

## AI에게: 실행 환경

- 터미널 명령을 실행할 수 없는 대화(일반 ChatGPT·Claude 대화)면 "Claude 데스크탑 앱의 Code 탭이나 ChatGPT 앱의 Work에서 다시 요청해 주세요"라고 안내하고 멈춘다.
- 작업 폴더로 이동해 `foodtapa-api.env`가 있는지 확인한다. 없으면 위 "작업 폴더와 접속 정보"대로 틀을 만들고 안내한 뒤 멈춘다. 내용을 확인할 때도 값은 출력하지 않고 네 이름이 있는지만 본다.
  ```sh
  for k in FOODTAPA_SITE FOODTAPA_USER FOODTAPA_APP_PASSWORD NOTION_TOKEN; do grep -q "^$k=." foodtapa-api.env && echo "$k 있음" || echo "$k 비어 있음"; done
  ```
- **노션 읽기**: AI 앱의 노션 커넥터(MCP)로 페이지와 하위 블록을 읽는다. 커넥터가 없고 `NOTION_TOKEN`이 채워져 있을 때만 `NOTION_TOKEN`으로 노션 API의 블록 목록(`GET https://api.notion.com/v1/blocks/{페이지 ID}/children`, 하위 블록이 있으면 재귀)을 읽는다. 둘 다 안 되면 노션 연결이나 토큰 준비를 안내하고 멈춘다. 404가 나면 그 페이지에 통합이 연결되지 않은 것이다.
- Windows에서는 아래 셸 명령을 같은 원칙(비밀값은 변수로만, 출력 금지)으로 PowerShell에 맞게 바꿔 실행한다.

## AI에게: 진행 순서

단계를 마칠 때마다 답변 맨 첫 줄에 완료를 표시한다. 실패하거나 건너뛴 단계는 ✅ 대신 ❌ 또는 ⏭️와 이유를 적는다.

```markdown
---

### ✅ 2단계 완료 · 글과 댓글 나누기

---
```

| 단계 | 할 일 |
| --- | --- |
| 1. 페이지 읽기 | 링크의 페이지 제목, 속성, 본문 블록을 하위 블록까지 읽는다. 블록 종류와 들여쓰기(부모·자식 관계)를 함께 본다. |
| 2. 글과 댓글 나누기 | 아래 "나누는 기준"대로 제목·본문·댓글·대댓글을 가른다. |
| 3. 전송할 JSON 만들기 | 아래 "필드 채우기" 표대로 `manuscript.json`을 작업 폴더에 UTF-8로 저장한다. 본문에 사진이 있으면 아래 "사진 넣기"대로 내려받아 한 장씩 올리고 받은 `upload_id`를 `post.images`에 넣는다. 올린 사진은 발행 전까지 공개되지 않고, 올린 지 24시간이 지나면 업로드 원본은 지워진다(원고에 넣은 사진은 접수 때 따로 보관된다). |
| 4. 사람 확인 | 아래 "확인 표"를 보여 주고 **전송** 답을 받는다. 고칠 곳을 답하면 노션 원문을 고쳐 달라고 하거나 나누기를 다시 해서 표를 다시 보여 준다. |
| 5. 전송 | 아래 "전송 방법"으로 보낸다. |
| 6. 결과 확인 | 접수 `id`로 상태를 1분 간격으로 최대 10번 조회한다. `passed`·`needs_revision`·`insufficient_evidence`·`error`가 되면 멈추고 보고한다. 10번 안에 끝나지 않으면 접수 번호와 함께 나중에 사이트에서 확인하라고 알린다. |
| 7. 발행·예약 | `passed`이고 페이지에 예약 일시가 있으면 아래 "발행·예약"대로 진행한다. 예약 일시가 없으면 이 단계는 건너뛴다. |

### 나누는 기준

- **제목**은 페이지 제목이나 본문 맨 위의 원고 제목이다. "LEARN-0001"처럼 관리용 번호만 붙은 페이지 제목이면 번호를 뺀 원고 제목을 쓴다. 어느 것이 원고 제목인지 애매하면 묻는다.
- **본문**은 제목 다음부터 첫 댓글 전까지의 원고 글이다. 관리용 메모, 원자료 정보, 검수 기록, 키워드 표시, 수정 전후 비교는 본문이 아니다.
- **댓글이 시작되는 곳**은 "댓글" 제목이나 구분선, 또는 "댓글1", "회원A:"처럼 화자가 붙은 첫 발화다.
- **대댓글의 부모**는 다음 순서로 정한다.
  1. 들여쓴 목록이면 바로 위 단계의 항목이 부모다.
  2. "1-1", "↳", "└", "→1"처럼 부모 번호나 답글 표시가 있으면 그 번호의 댓글이 부모다.
  3. 둘 다 없으면 부모를 짐작하지 않고 사람에게 묻는다.
- 같은 원고를 수정해 다시 보낼 때는 처음 보낼 때와 같은 방식으로 댓글 ID를 만든다.

### 필드 채우기

| 필드 | 값 | 없을 때 |
| --- | --- | --- |
| `source_id` | 페이지의 S소스·원문 ID | 묻는다 |
| `manuscript_id` | 페이지의 원고 ID(예: `LEARN-0654`) | 묻는다 |
| `source_scope` | 이 원고가 다루는 질문과 활용 범위. 페이지의 검색질문·활용 범위를 그대로 옮긴다 | 묻는다 |
| `mode` | 유형. 검색형 `search`, 생활형 `life`, 일상형 `daily` | 묻는다 |
| `keyword` | 목표 키워드 하나 | 검색형이면 묻는다. 그 밖에는 빈 문자열 |
| `version` | AI가 정함. 아래 "버전 만들기" | |
| `notion_url` | 요청받은 링크 | |
| `post.type` | 질문 `question`, 후기 `review`, 정보글 `guide`. 페이지에 적혀 있으면 그대로 쓰고, 없으면 AI가 본문을 보고 정해 확인 표에 표시한다. 정보글은 "핵심 답변", "조건별 차이", "확인 방법" 소제목이 이 순서로 있어야 구조 검수를 통과한다 | |
| `post.title`, `post.content` | 나눈 제목과 본문. 본문의 줄바꿈은 그대로 둔다 | |
| `post.speaker` | 글쓴이 `author` | |
| `post.images` | 본문의 사진. 아래 "사진 넣기" | 빼거나 빈 목록 |
| `post.taxonomies` | 페이지에 제품군·브랜드·모델·주제·상황 이름이 있으면 각 목록에 넣는다. 사이트에 등록된 이름과 글자까지 같아야 한다 | 다섯 항목 모두 빈 목록 |
| `comments[].id` | 원고의 댓글 번호를 `c1`, `c1-1`처럼 바꾼다. 번호가 없으면 노션 블록 ID에서 하이픈을 뺀 값을 쓴다. 영문·숫자와 `-`만 쓴다 | |
| `comments[].parent_id` | 대댓글이면 부모 댓글의 `id`. 첫 단계 댓글은 넣지 않는다 | |
| `comments[].speaker` | 글쓴이는 `author`. 다른 회원은 처음 나온 순서대로 `member-1`, `member-2`. 같은 이름은 원고 안에서 같은 값 | |
| `comments[].content` | 화자 표시와 번호를 뗀 댓글 본문 그대로 | |
| `evidence` | 페이지에 정제된 사실 근거가 따로 적혀 있을 때만 넣는다. S소스 원문을 통째로 넣지 않는다 | 빈 문자열 |

### 사진 넣기

- 정보글(`guide`)에는 사진을 넣지 않는다. 정보글 페이지에 사진이 있으면 보내지 말고 사람에게 알린다.
- 제목부터 첫 댓글 전까지 본문에 있는 노션 이미지 블록만 넣는다. 위에서부터 차례로 `photo-1`, `photo-2`처럼 `id`를 붙인다. 같은 원고를 다시 보낼 때도 같은 순서로 붙인다.
- 이미지 블록의 파일 주소(노션에 올린 파일이면 `image.file.url`, 외부 링크면 `image.external.url`)에서 작업 폴더의 `photos/`로 내려받는다. 노션 파일 주소는 1시간쯤 지나면 만료되므로 만료됐으면 페이지를 다시 읽어 새 주소를 받는다. 주소는 화면에 출력하지 않는다.
- 사진은 원고 JSON에 base64로 넣지 않는다. 내려받은 사진을 한 장씩 사이트에 올리고 응답의 `upload_id`를 받는다. 인증은 "전송 방법"과 같이 표준 입력으로 넘긴다.
  ```sh
  set -a; . ./foodtapa-api.env; set +a
  api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
  printf 'user = "%s:%s"\n' "$FOODTAPA_USER" "$FOODTAPA_APP_PASSWORD" | curl -sS -K - \
    -F "file=@photos/photo-1.jpg" -w '\nHTTP %{http_code}\n' "$api/images"
  ```
- `201`은 새로 올림, `200`은 같은 사진을 이미 올려 기존 `upload_id`를 돌려준 것이다. `422`면 응답의 `data.reason`(형식·5MB·화소)을 알리고, 직접 바꾸지 말고 사람에게 노션의 사진을 바꿔 달라고 한다.
- `post.images`에는 사진마다 `{"id": "photo-1", "upload_id": "응답의 upload_id", "alt": ""}`를 넣는다.
- 수정 반영으로 새 버전을 보낼 때는 내려받은 사진마다 SHA-256을 계산해(`shasum -a 256 사진파일`) 직전 접수 상태 조회 응답 `payload.post.images`의 `sha256`과 비교한다. 같은 사진은 올리지 않고 `{"id": "photo-1", "sha256": "그 값", "alt": ""}`로 넣는다. 새로 생긴 사진만 올려 `upload_id`로 넣고, 노션에서 빠진 사진은 목록에서 뺀다. 확인 표에 사진마다 재사용·새로 올림을 표시한다. `upload_id`는 24시간 동안만 쓸 수 있다. 접수가 `post.images[순번].upload_id` 오류로 돌아오면 그 사진을 다시 올려 새 `upload_id`로 바꿔 넣는다.
- 이미지 캡션이 있으면 `alt`에 넣는다. HTML 없이 한 줄 200자 이내로 쓰고 이름·연락처 같은 개인정보는 넣지 않는다. 캡션이 없으면 빈 문자열로 둔다.
- 사이트는 JPG·PNG·WEBP 사진을 장당 5MB 이하로 10장까지 받는다. 형식이 다르거나(GIF·HEIC 등) 크기를 넘으면 직접 바꾸지 말고 사람에게 알려 노션의 사진을 바꿔 달라고 한다.
- 사진을 본문에 `<img>` 태그나 `style`의 배경 이미지(`url()`)로 넣지 않는다. 댓글 사이에 있는 사진은 보낼 수 없으니 사람에게 알리고 어떻게 할지 묻는다.

페이지의 **예약 일시**는 `manuscript.json`에 넣지 않는다. 검수를 통과한 뒤 7단계 발행 요청에만 쓴다.

**버전 만들기**: 처음 보내거나 원고를 고쳤을 때는 `version`을 비우고 `notion_url`을 뺀 JSON을 키 순서대로 정렬해 한 줄로 만든다. SHA-256 앞 12자리에 `v-`를 붙인다.

```sh
canonical=$(jq -ceS '.version = "" | del(.notion_url)' manuscript.json) &&
  v="v-$(printf '%s\n' "$canonical" | shasum -a 256 | cut -c1-12)"
```

이 값을 `version`에 넣어 다시 저장한다. 같은 원고를 재전송하거나 노션 링크만 바꿀 때는 처음 보낸 `version`을 그대로 쓴다. 같은 사진을 다시 올려 `upload_id`만 바꿀 때도 그대로 쓴다.

### 확인 표

전송 전에 아래 두 표를 보여 준다. 본문 글자 수는 줄바꿈을 빼고 공백을 포함해 센다.

| 항목 | 값 |
| --- | --- |
| 원고 ID / 원자료 ID | |
| 유형 / 글 종류 | 글 종류를 AI가 정했으면 "(AI 판단)"을 붙인다 |
| 목표 키워드 / 제목 속 횟수 | |
| 제목 | |
| 본문 글자 수 | 검색형·생활형이거나 키워드가 있으면 350자 이상이어야 통과한다 |
| 댓글 수 / 대댓글 수 | |
| 사진 | 장수와 사진마다 `id`·형식·크기·업로드 결과(올림·이미 올림·오류). 없으면 "없음" |

제목 키워드가 1회가 아니거나 본문이 350자 미만이면 표 아래에 "이대로 보내면 수정 필요로 돌아옵니다"라고 알린다. 사람이 그래도 보내라고 하면 보낸다.

### 전송 방법

비밀값이 화면과 명령 인자에 남지 않게 설정 파일을 셸 변수로 읽고, 인증은 표준 입력으로 curl에 넘긴다.

```sh
set -a; . ./foodtapa-api.env; set +a
api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
printf 'user = "%s:%s"\n' "$FOODTAPA_USER" "$FOODTAPA_APP_PASSWORD" | curl -sS -K - \
  -H 'Content-Type: application/json' --data-binary @manuscript.json \
  -w '\nHTTP %{http_code}\n' "$api"
```

- `202`는 새로 접수, `200`은 같은 원고·버전을 이미 접수해 기존 결과를 돌려준 것이다. 응답의 `id`를 기록한다.
- `409`는 같은 원고 ID·버전에 다른 내용이 있거나 원고 ID가 다른 원자료에 묶인 경우다. `422`는 필드가 잘못된 경우다. 응답의 `message`를 그대로 알리고 고칠 곳을 설명한다. 같은 요청을 반복하지 않는다.
- `401`·`403`이면 Application Password나 권한 문제다. 비밀값을 확인하겠다며 파일을 출력하지 말고 사람에게 다시 만들어 넣어 달라고 한다.

상태 조회는 같은 방식으로 `"$api/{id}/status"`에 빈 본문 `{}`을 POST로 보낸다.

## AI에게: 수정 반영 순서

사람이 "수정 반영"을 요청하면 아래 순서로 진행한다. 단계 완료 표시는 검수 보내기와 같다.

| 단계 | 할 일 |
| --- | --- |
| 1. 페이지 읽기 | 검수 보내기 1~3단계와 같이 페이지를 읽고 나눈다. 원고 ID(`manuscript_id`)를 확인한다. |
| 2. 검수 의견 받기 | 아래 "검수 의견 조회"로 이 원고의 최신 접수 건을 찾고 `status`를 조회한다. 최신 건이 `needs_revision`·`insufficient_evidence`가 아니면 고치지 않고 현재 상태만 알린다. |
| 3. 고칠 안 만들기 | `issues`마다 `target`(위치)과 `excerpt`(문제 문장)로 노션의 해당 블록을 찾고 `reason`·`suggestion`에 맞춰 고칠 문장을 만든다. |
| 4. 사람 확인 | 아래 "수정 안 표"를 보여 주고 **반영** 답을 받는다. 사람이 고친 문장을 주면 그 문장을 쓴다. |
| 5. 노션 고치기 | 확인받은 블록만 노션 커넥터(또는 `NOTION_TOKEN`으로 노션 API의 블록 수정 `PATCH https://api.notion.com/v1/blocks/{블록 ID}`)로 고친다. 고친 뒤 페이지를 다시 읽어 바뀐 문장을 확인한다. |
| 6. 다시 보내기 | 다시 읽은 페이지로 검수 보내기 2~6단계를 진행한다. 원자료 ID·원고 ID·댓글 ID는 처음과 같게 두고, `version`은 내용이 바뀌었으니 새 해시로 정해진다. |

### 고치는 기준

- **지적된 곳만 고친다.** `issues`에 없는 문장, 말투, 줄바꿈은 그대로 둔다.
- **같은 화자·같은 흐름을 지킨다.** 댓글을 지우거나 순서·부모 연결·화자를 바꿔야 하면 고치지 말고 사람에게 묻는다.
- **근거를 만들지 않는다.** 사실 근거 부족(`evidence` 항목이나 `insufficient_evidence`)은 근거를 지어내지 않는다. 페이지에 정제된 근거가 있으면 `evidence`에 넣고, 없으면 단정한 문장을 "~라고 들었어요"처럼 경험·질문으로 낮추는 안과 근거를 보태 달라는 요청을 함께 보여 준다.
- **사진은 AI가 고치지 않는다.** 사진 지적(`check`가 `image`)은 `target`의 사진 `id`가 노션의 몇 번째 사진인지와 `reason`의 발견 종류를 알려 주고, 사람이 노션에서 그 부분을 가리거나 다른 사진으로 바꾼 뒤 다시 보내게 한다.
- **규칙 검사는 기준을 맞춘다.** 본문 350자 미만이면 글쓴이 말투로 상황을 보태는 안을, 제목 키워드가 0회·2회 이상이면 키워드가 정확히 한 번 들어간 제목 안을 보여 준다. 개인정보는 해당 부분을 지우거나 일반화한다.
- **개인정보 지적에는 문제 문장이 없다.** `check`가 `privacy`이면 `excerpt`가 비어 있다. `target` 위치에서 `reason`에 적힌 종류(예: 전화번호)로 보이는 값을 찾아 표에 보여 준다. 모델 번호처럼 개인정보가 아닌 값이면 고치지 말고 사람에게 알린다. 사람이 오탐이라고 판단하면 아래 "관리자 허용 요청"으로 진행한다.

### 검수 의견 조회

```sh
set -a; . ./foodtapa-api.env; set +a
api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
printf 'user = "%s:%s"\n' "$FOODTAPA_USER" "$FOODTAPA_APP_PASSWORD" | curl -sS -K - \
  -H 'Content-Type: application/json' --data '{"search":"원고 ID","orderby":"id","order":"desc"}' \
  "$api/query"
```

- 결과에서 `manuscript_id`가 정확히 같은 첫 항목이 최신 접수 건이다. 그 `id`로 `"$api/{id}/status"`를 조회한다.
- 수정이 필요한 원고 전체를 보려면 `{"view":"revise"}`로 조회한다. 이 경우에도 고치는 것은 요청받은 링크의 원고 하나뿐이다.

### 수정 안 표

| 항목 | 위치 | 지금 문장 | 고칠 문장 | 이유 |
| --- | --- | --- | --- | --- |

`check`가 비었거나 `other`이면 항목을 "기타"로 적는다. 표 아래에 "반영하면 노션 원고가 바뀌고 새 버전으로 다시 검수됩니다"라고 알린다.

## AI에게: 관리자 허용 요청

개인정보가 아닌 값이 개인정보로 잡혔거나(예: 모델 번호가 전화번호로 잡힘) AI 검수 판정이 맞지 않을 때, 사람이 오탐이라고 판단하면 원고를 고치지 않고 그 버전을 통과시킬 수 있다. AI가 오탐인지 스스로 정하지 않는다. 사람이 **허용**을 요청했을 때만 진행한다.

1. "검수 의견 조회"로 이 원고의 최신 접수 건을 찾는다. 최신 건이 `needs_revision`·`insufficient_evidence`가 아니면 허용하지 않고 현재 상태만 알린다.
2. 허용 사유를 사람에게 받는다. 사유는 필수이며 짐작해 채우지 않는다. 1,000자 이내로 쓰고 이름·연락처 같은 개인정보는 넣지 않는다.
3. 아래 표를 보여 주고 **허용** 답을 받는다.

   | 항목 | 값 |
   | --- | --- |
   | 원고 ID / 버전 / 접수 번호 | |
   | 허용할 지적 | 위치와 항목(예: 본문 · 개인정보 전화번호) |
   | 허용 사유 | |

4. 같은 인증 방식으로 `"$api/{접수 id}/override"`에 `{"reason":"허용 사유"}`를 POST로 보낸다. 사유는 셸 변수나 파일로 넘겨 JSON 따옴표가 깨지지 않게 한다.
5. 응답의 `status`가 `passed`이고 `override`에 사유가 담겼는지 확인해 보고한다. 지적은 기록으로 남아 `checks`에 미충족으로 계속 보인다고 알린다. 이후 발행은 "발행·예약" 순서대로 한다.

- `409`는 최신 버전이 아니거나 허용할 수 없는 상태, 또는 개인정보 제거 표시가 남은 원고다. `422`는 사유가 비었거나 길거나 개인정보로 보이는 값이 있는 경우다. 응답의 `message`를 그대로 알리고 반복하지 않는다.
- 이미 허용한 건에 다시 보내면 처음 기록이 그대로 돌아온다.

## AI에게: 발행·예약

이 요청이 사이트의 발행 승인이다. 사람이 **발행**이라고 답하기 전에는 보내지 않는다.

1. 페이지의 예약 일시를 한국 시간으로 읽어 `2026-12-01T09:00:00+09:00` 형식으로 바꾼다. 날짜만 있고 시각이 없거나 이미 지난 시각이면 짐작하지 않고 묻는다.
2. 아래 표를 보여 주고 **발행** 답을 받는다.

   | 항목 | 값 |
   | --- | --- |
   | 원고 ID / 버전 | |
   | 제목 | |
   | 발행 방식 | 예약 (한국 시간 날짜·시각) |
   | 함께 공개될 댓글 수 | 글이 공개될 때 함께 등록됩니다 |

3. 같은 인증 방식으로 `"$api/{접수 id}/publish"`에 `{"status":"future","date":"2026-12-01T09:00:00+09:00"}`를 POST로 보낸다. 사람이 지금 바로 공개하라고 하면 `{"status":"publish"}`로 보낸다.
4. 응답의 `status`가 `future`인지, `date_gmt`가 요청 시각과 같은지(UTC라 한국 시간에서 9시간 뺀 값) 확인하고 `edit_url`과 함께 보고한다. `comments_skipped`가 1 이상이면 관리자가 보류·폐기한 댓글이 빠졌다고 알린다.

- 예약 시각을 바꿀 때도 같은 요청을 새 시각으로 다시 보낸다. 같은 글의 예약 시각만 바뀐다. `date`에는 반드시 `+09:00`을 붙인다.
- `409`에 "운영자가 보류한 글입니다"가 오면 반복하지 말고 사이트 관리자에게 보류 해제를 요청하라고 알린다.
- `500`에 `fdtw_external_image_attach`가 오면 글은 임시저장으로 돌아가 있다. 같은 요청을 한 번 다시 보내고, 또 실패하면 멈추고 알린다.
- 그 밖의 `409`·`422`는 응답의 `message`와 `data.reason`을 그대로 알리고 반복하지 않는다.

## AI에게: 막힐 때

- **글과 댓글의 경계가 애매함**: 애매한 줄을 그대로 보여 주고 본문인지 댓글인지 묻는다. 짐작해 보내지 않는다.
- **같은 화자인지 애매함**: 이름이 조금 다른 두 화자(예: "회원A", "A님")가 같은 사람인지 묻는다.
- **노션 페이지를 못 읽음**: 연결이나 토큰 문제인지 알리고 멈춘다. 다른 방법으로 페이지 내용을 구하지 않는다.
- **검수가 `error`**: 사이트 관리자 화면의 **자동화 → 외부 원고 검수 → 검수 목록**에서 다시 실행할 수 있다고 알린다.

상태 조회 응답의 `checks`를 표로 보여 준다. `state`는 `pass` 충족, `fail` 미충족, `na` 해당 없음, `skipped` 검사 전으로 옮긴다. `issues`가 있으면 위치(`target`), 이유(`reason`), 고칠 방향(`suggestion`)을 표로 덧붙인다.

마지막에 다음을 안내한다. "수정이 필요하면 노션 원고를 직접 고쳐 같은 링크로 다시 보내거나, **노션 원고 수정 반영해 주세요**로 요청해 주세요. 어느 쪽이든 새 버전으로 검수됩니다. 개인정보가 아닌 값이 잡혔거나 판정이 맞지 않으면 사유와 함께 **관리자 허용**을 요청할 수 있습니다. 통과한 원고는 노션 페이지에 예약 일시를 적고 다시 요청하거나, 사이트 관리자 화면의 **자동화 → 외부 원고 검수 → 검수 목록**에서 발행 승인으로 보낼 수 있습니다."

# 노션 원고 수정 반영

## 시작 전에

- 이 스킬은 푸드타파 플러그인의 세부 스킬이다. 작업 폴더와 접속 정보, 보낼 사이트, 지켜야 할 규칙, 실행 환경, 전송 방법(인증)은 메인 스킬 `foodtapa-notion-review`의 같은 이름 절을 따른다. 이 대화에서 아직 읽지 않았으면 이 스킬 폴더 옆의 `../foodtapa-notion-review/SKILL.md`에서 그 절을 먼저 읽는다.
- 사이트 API 판단 기준은 `../foodtapa-notion-review/references/api.md`를 따른다. 사이트 API는 바뀔 수 있으므로 판단은 사이트 응답, 사이트가 알려 주는 목록, 이 지침 순서로 한다.
- 사이트가 `200`·`201`·`202`가 아닌 응답을 주면 `foodtapa-review-errors` 스킬을 불러 따른다. 부를 수 없으면 `../foodtapa-review-errors/SKILL.md`를 읽는다.
- 아래 명령의 `$api`는 메인 스킬 "전송 방법"과 같이 정한다.

  ```sh
  set -a; . ./foodtapa-api.env; set +a
  api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
  ```
- 노션 원고 링크가 요청에 없으면 그것 하나만 묻는다. 한 번에 원고 한 편만 고친다.

## AI에게: 수정 반영 순서

사람이 "수정 반영"을 요청하면 아래 순서로 진행한다. 단계 완료 표시는 메인 스킬 진행 순서와 같다.

| 단계 | 할 일 |
| --- | --- |
| 1. 페이지 읽기 | 메인 스킬 진행 순서 1~3단계와 같이 페이지를 읽고 나눈다. 원고 ID(`manuscript_id`)를 확인한다. |
| 2. 검수 의견 받기 | 아래 "검수 의견 조회"로 이 원고의 최신 접수 건을 찾고 `status`를 조회한다. 최신 건이 `needs_revision`·`insufficient_evidence`가 아니면 고치지 않고 현재 상태만 알린다. |
| 3. 고칠 안 만들기 | `issues`마다 `target`(위치)과 `excerpt`(문제 문장)로 노션의 해당 블록을 찾고 `reason`·`suggestion`에 맞춰 고칠 문장을 만든다. |
| 4. 사람 확인 | 아래 "수정 안 표"를 보여 주고 **반영** 답을 받는다. 사람이 고친 문장을 주면 그 문장을 쓴다. |
| 5. 노션 고치기 | 확인받은 블록만 노션 커넥터(또는 `NOTION_TOKEN`으로 노션 API의 블록 수정 `PATCH https://api.notion.com/v1/blocks/{블록 ID}`)로 고친다. 고친 뒤 페이지를 다시 읽어 바뀐 문장을 확인한다. |
| 6. 다시 보내기 | 다시 읽은 페이지로 메인 스킬 진행 순서 2~6단계를 진행한다. 원자료 ID·원고 ID·댓글 ID는 처음과 같게 두고, `version`은 내용이 바뀌었으니 새 해시로 정해진다. |

### 고치는 기준

- **지적된 곳만 고친다.** `issues`에 없는 문장, 말투, 줄바꿈은 그대로 둔다.
- **같은 화자·같은 흐름을 지킨다.** 댓글을 지우거나 순서·부모 연결·화자를 바꿔야 하면 고치지 말고 사람에게 묻는다.
- **근거를 만들지 않는다.** 사실 근거 부족(`evidence` 항목이나 `insufficient_evidence`)은 근거를 지어내지 않는다. 페이지에 정제된 근거가 있으면 `evidence`에 넣고, 없으면 단정한 문장을 "~라고 들었어요"처럼 경험·질문으로 낮추는 안과 근거를 보태 달라는 요청을 함께 보여 준다.
- **사진은 AI가 고치지 않는다.** 사진 지적(`check`가 `image`)은 `target`의 사진 `id`가 노션의 몇 번째 사진인지와 `reason`의 발견 종류를 알려 주고, 사람이 노션에서 그 부분을 가리거나 다른 사진으로 바꾼 뒤 다시 보내게 한다.
- **규칙 검사는 기준을 맞춘다.** 본문 350자 미만이면 글쓴이 말투로 상황을 보태는 안을, 제목 키워드가 0회·2회 이상이면 키워드가 정확히 한 번 들어간 제목 안을 보여 준다. 개인정보는 해당 부분을 지우거나 일반화한다.
- **개인정보 지적에는 문제 문장이 없다.** `check`가 `privacy`이면 `excerpt`가 비어 있다. `target` 위치에서 `reason`에 적힌 종류(예: 전화번호)로 보이는 값을 찾아 표에 보여 준다. 모델 번호처럼 개인정보가 아닌 값이면 고치지 말고 사람에게 알린다. 사람이 오탐이라고 판단하면 `foodtapa-review-override` 스킬로 진행한다.

### 검수 의견 조회

```sh
set -a; . ./foodtapa-api.env; set +a
api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
printf 'user = "%s:%s"\n' "$FOODTAPA_USER" "$FOODTAPA_APP_PASSWORD" | curl -sS -K - \
  -H 'Content-Type: application/json' --data '{"search":"원고 ID","orderby":"id","order":"desc"}' \
  "$api/query"
```

- 결과에서 `manuscript_id`가 정확히 같은 첫 항목이 최신 접수 건이다. 그 `id`로 `"$api/{id}/status"`를 조회한다.
- 수정이 필요한 원고 전체를 보려면 `{"view":"revise"}`로 조회한다. 이 경우에도 고치는 것은 요청받은 링크의 원고 하나뿐이다.

### 수정 안 표

| 항목 | 위치 | 지금 문장 | 고칠 문장 | 이유 |
| --- | --- | --- | --- | --- |

`check`가 비었거나 `other`이면 항목을 "기타"로 적는다. 표 아래에 "반영하면 노션 원고가 바뀌고 새 버전으로 다시 검수됩니다"라고 알린다.

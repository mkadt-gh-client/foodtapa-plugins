# 오류 대응

## 시작 전에

- 이 스킬은 푸드타파 플러그인의 세부 스킬이다. 작업 폴더와 접속 정보, 보낼 사이트, 지켜야 할 규칙, 실행 환경, 전송 방법(인증)은 메인 스킬 `foodtapa-notion-review`의 같은 이름 절을 따른다. 이 대화에서 아직 읽지 않았으면 이 스킬 폴더 옆의 `../foodtapa-notion-review/SKILL.md`에서 그 절을 먼저 읽는다.
- 사이트 API 판단 기준은 `../foodtapa-notion-review/references/api.md`를 따른다. 사이트 API는 바뀔 수 있으므로 판단은 사이트 응답, 사이트가 알려 주는 목록, 이 지침 순서로 한다.
- 아래 명령의 `$api`는 메인 스킬 "전송 방법"과 같이 정한다.

  ```sh
  set -a; . ./foodtapa-api.env; set +a
  api="$FOODTAPA_SITE/wp-json/fdt/v1/workflows/external-reviews"
  ```


이 문서는 2026-11-25에 kincomm과 음식물처리기.net에서 실제로 오류를 일으켜 확인한 내용이다. 사이트 API는 바뀔 수 있으므로 `../foodtapa-notion-review/references/api.md`의 "판단 기준"을 먼저 따른다. 아래 표에 없는 응답이 와도 같은 순서로 판단한다.

## 판단 순서

1. **HTTP 상태로 성격을 가른다.**

   | 상태 | 성격 | 기본 행동 |
   | --- | --- | --- |
   | `400`·`405` | AI가 요청을 잘못 만듦 | AI가 요청을 고쳐 다시 보낸다. 사람에게 고쳐 달라고 하지 않는다 |
   | `401`·`403` | 인증·권한 | 아래 "인증과 권한" |
   | `404` | 접수 번호를 못 찾음 | 조회(`$api/query`)로 원고 ID의 접수를 다시 찾는다 |
   | `409` | 지금 상태에서는 할 수 없음 | 같은 요청을 반복하지 않는다. 최신 접수 상태를 다시 조회하고 아래 표대로 안내한다 |
   | `422` | 보낸 내용이 틀림 | 위치(`data.field`)와 이유(`data.reason`)로 노션의 고칠 곳을 짚는다 |
   | `500`·`502`·`503` | 사이트 쪽 문제 | 1분 뒤 한 번만 다시 보낸다. 또 실패하면 멈추고 사이트 관리자에게 전달할 내용을 알린다 |

2. **고칠 주체를 가른다.** 위치가 AI가 만든 값(`version`, 댓글 `id`·`parent_id` 형식, `speaker` 형식, 사진 `upload_id`·`sha256`)이면 AI가 노션 원문을 다시 읽어 고친다. 고친 뒤에는 확인 표를 다시 보여 주고 전송 확인을 받는다. 노션에 적힌 값이 틀렸으면 사람에게 노션에서 고쳐 달라고 한다.
3. **사람에게는 노션 말로 알린다.** 응답 문구에 `post.images`·`upload_id` 같은 API 용어가 있으면 그대로 옮기지 말고 아래 "위치 읽는 법"으로 노션의 어느 칸인지 풀어 쓴다. 원래 `message`는 표 아래에 한 줄로 덧붙인다.
4. **같은 요청을 그대로 다시 보내지 않는다.** 다시 보내는 것은 고친 뒤이거나 5xx를 한 번 다시 시도할 때뿐이다.

| `reason` | 관리자 허용 사유 | 사람 |
| `date` | 페이지의 예약 일시 | AI가 형식을 고침. 지난 시각이면 사람 |
| `file` | 올리려던 사진 파일 | 사람 |

## 접수 (`$api`)

| 응답 | 뜻 | 할 일 |
| --- | --- | --- |
| `422` 원자료 ID·원고 ID·버전 확인 | ID가 비었거나 형식이 틀림(영문·숫자로 시작하고 영문·숫자와 `_ . : -`만, 191자 이내) | 노션 관리 정보의 ID를 고쳐 달라고 한다. 한글·공백이 있으면 그것을 짚는다 |
| `422` 유형 | 유형이 검색형·생활형·일상형이 아님 | 노션 유형 칸을 고쳐 달라고 한다 |
| `422` 제목·본문·화자 | 제목이 비었거나 250자 초과, 본문에 `<img>`·배경 이미지가 있음 등 | 이유대로 안내한다. 본문 속 사진 태그는 노션 이미지 블록으로 바꿔 달라고 한다 |
| `422` 글 종류 | 질문·후기·정보글이 아님 | 노션 글 종류 칸을 고치거나, AI가 정했으면 다시 정한다 |
| `422` 등록된 분류에서 선택 | 사이트에 없는 분류 이름 | 사이트의 등록 목록(`../foodtapa-notion-review/references/api.md` "판단 기준" 5)을 보여 주고 노션의 이름을 그중 하나로 고쳐 달라고 한다. 새 분류가 필요하면 사이트 관리자가 먼저 등록해야 한다고 알린다 |
| `422` 댓글·대댓글 확인 | 댓글 번호 중복·형식, 화자 형식, 댓글 100개 초과 | 위치를 보고 AI가 번호·화자 값을 다시 만든다. 100개 초과는 사람에게 알린다 |
| `422` 대댓글의 부모 | 부모 댓글이 같은 원고에 없거나 연결이 순환함 | 노션의 들여쓰기·답글 표시를 다시 읽는다. 그래도 부모가 없으면 어느 댓글에 단 답인지 묻는다 |
| `422` 정보글은 사진을 첨부할 수 없음 | 정보글에 사진 | 사진을 빼거나 글 종류를 바꿀지 묻는다 |
| `422` 사진(`upload_id`) | 올린 사진을 못 찾음. 24시간이 지났거나 다른 계정으로 올림 | AI가 그 사진을 다시 올려 새 `upload_id`로 바꾼다. 버전은 그대로 둔다 |
| `422` 사진(`sha256`) | 이전 접수에 없는 사진을 재사용하려 함 | AI가 그 사진을 새로 올려 `upload_id`로 넣는다 |
| `422` 목표 키워드와 근거 | 키워드·활용 범위·근거 형식이 틀림 | 위치를 보고 노션의 해당 칸을 고쳐 달라고 한다 |
| `422` 합계가 너무 김 | 본문·댓글·근거를 합친 길이 초과 | 근거를 줄이거나 원고를 나눌지 묻는다 |
| `409` 같은 원고 ID와 버전에 다른 내용 | 원고가 바뀌었는데 버전이 같음 | AI가 버전을 다시 계산한다(메인 스킬 `foodtapa-notion-review`의 "버전 만들기"). 내용을 바꾸지 않았는데도 나오면 처음 보낸 내용과 무엇이 다른지 비교해 보여 준다 |
| `409` 이 원고 ID는 다른 원자료와 연결 | 원고 ID는 같은데 원자료 ID가 처음과 다름 | 조회로 처음 접수의 `source_id`를 찾아 보여 주고, 노션의 원자료 ID·원고 ID 중 무엇이 맞는지 묻는다 |
| `400` JSON으로 보내 주세요 | 보낸 파일이 JSON이 아님 | AI가 `manuscript.json`을 다시 만든다 |
| `500` 저장하지 못함 | 사이트 저장 오류 | 1분 뒤 한 번 다시 보낸다 |
| `503` 사진 메타데이터를 지우는 기능 | 사이트 서버 설정 문제 | 사진 없이 보낼지 묻거나 사이트 관리자에게 알린다 |

## 사진 올리기 (`$api/images`)

| 응답 | 할 일 |
| --- | --- |
| `422` | `data.reason`(형식·5MB·빈 파일·화소)을 알리고 노션의 그 사진을 JPG·PNG·WEBP, 5MB 이하로 바꿔 달라고 한다. AI가 직접 변환하지 않는다 |
| `503` | 사이트 서버 설정 문제다. 사이트 관리자에게 알린다 |

## 검수가 오류로 끝남 (`status`가 `error`)

`error` 문구는 원인을 알려 주지 않는다. 아래 순서로 원인을 찾는다.

1. `../foodtapa-notion-review/references/api.md`의 "AI 상태"로 조회한다.
2. 이 사이트가 쓰는 제공사(`models`가 비어 있지 않은 쪽)를 본다.
   - `미등록`: 사이트에 AI 키가 없어 검수할 수 없다. 다시 실행해도 같다. "사이트 관리자 화면의 **자동화 → AI API 연결**(`$FOODTAPA_SITE/wp-admin/admin.php?page=fdtw-ai-connection`)에서 키를 등록해야 검수됩니다"라고 알리고 `foodtapa-setup` 스킬의 "AI 키 등록"으로 이어 간다.
   - `키를 읽지 못함`·`연결 실패`: 키가 틀렸거나 사용 한도·결제 문제일 수 있다. 모델의 `error` 또는 `last_request.error`에 있는 안내 문구를 그대로 전하고, 관리자 화면에서 키를 확인해 달라고 한 뒤 멈춘다.
   - `연결됨`·`연결 확인 필요`: 일시 오류일 수 있다. 3으로 간다.
3. `$api/{id}/retry`에 `{}`를 보내 한 번만 다시 실행한다. `202`면 메인 스킬 진행 순서 6단계처럼 다시 상태를 조회한다. 또 `error`면 멈추고 접수 번호와 함께 사이트 관리자에게 알리라고 한다.
4. retry가 `409`면 이미 다른 상태다. 상태를 다시 조회해 보고한다.

10번 조회해도 `queued`·`running`이면 오류가 아니다. 사이트는 검수를 1분에 한 건씩 차례로 처리하므로 앞에 쌓인 건이 많을 수 있다. 접수 번호를 알려 주고 나중에 "검수 결과 확인해 주세요"로 다시 요청하라고 안내한다.

## 관리자 허용 (`$api/{id}/override`)

| 응답 | 할 일 |
| --- | --- |
| `422` 사유를 적어 주세요 | 사유가 비었거나 1,000자를 넘음. 사람에게 사유를 다시 받는다 |
| `422` 개인정보로 보이는 값 | 사유에 전화번호 같은 값이 있음. 찾은 종류만 알리고 그 값을 뺀 사유를 받는다 |
| `409` 최신 버전에서 수정 필요나 근거 부족 | 최신 접수가 아니거나 이미 다른 상태다. 조회로 최신 접수를 찾아 상태를 알린다 |
| `409` 개인정보 제거 표시 | 노션 원고에 가림 표시가 남아 있다. 표시를 지운 새 버전으로 보내야 한다고 알린다 |
| `200`인데 처음 기록 | 이미 허용한 건이다. 처음 허용 기록을 그대로 보고한다 |

## 발행 (`$api/{id}/publish`)

| 응답 | 할 일 |
| --- | --- |
| `422` 시간대 / 지금보다 뒤 | 예약 일시를 `+09:00`을 붙인 형식으로 다시 만든다. 지난 시각이면 사람에게 새 일시를 묻는다. 날짜가 빠졌거나 형식이 틀려도 "시간대" 문구가 나오므로 보낸 `date` 값부터 확인한다 |
| `400` 유효하지 않은 파라미터 | `status` 값이 틀림. 라우트 목록의 허용값으로 고친다 |
| `409` 검수를 통과한 원고만 / 최신 버전 | 통과하지 않았거나 새 버전이 있다. 조회로 최신 접수를 찾아 상태를 알린다 |
| `409` 운영자가 보류한 글 | 반복하지 않는다. 사이트 관리자에게 보류 해제를 요청하라고 알린다 |
| `409` 발행할 글을 찾을 수 없음 | 관리자가 글을 지웠을 수 있다. 사이트 관리자에게 알린다 |
| `422` 개인정보·근거 원문 복사·정보글 구조 | 발행용 원고를 만들 때 걸렸다. `message`를 알리고 노션에서 고쳐 새 버전으로 보내라고 한다 |
| `500` 사진을 붙이지 못함 | `data.reason`대로다. 글은 임시저장으로 돌아가 있거나 사진 없이 등록돼 있다. 같은 요청을 한 번 다시 보내고, 또 실패하면 멈추고 알린다 |
| `403` 발행 승인 권한 | 계정 권한 문제다. 아래 "인증과 권한" |

## 인증과 권한

| 응답 | 할 일 |
| --- | --- |
| `401` | 애플리케이션 비밀번호가 틀렸거나 지워졌다. `foodtapa-api.env`를 출력하지 말고 `foodtapa-setup` 스킬로 파일을 열어 새로 만든 값을 직접 넣게 한다 |
| `403` | 계정에 관리자 권한(다른 사람 글 편집·댓글 관리)이 없다. `foodtapa-setup` 스킬로 파일을 열어 관리자 계정의 아이디와 그 계정에서 만든 애플리케이션 비밀번호로 바꾸게 한다 |

## 미리 막는 함정

아래는 사이트가 오류를 내지 않거나 원인을 다르게 알려 주는 경우다. 메인 스킬의 "필수 정보 점검"에서 보내기 전에 막는다.

- 검색형인데 목표 키워드가 비어도 접수된다. 결과는 "제목 키워드 1회" 미충족으로만 나온다.
- 분류 축 이름이 틀리면(`brands` 등) 오류 없이 그 분류가 빠진다. 축 이름은 `product`·`brand`·`model`·`topic`·`situation` 다섯만 쓴다.
- 예약 날짜가 없어도 "시간대" 오류로 나온다.
